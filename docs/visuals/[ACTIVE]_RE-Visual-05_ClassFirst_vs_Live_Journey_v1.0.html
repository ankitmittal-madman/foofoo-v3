RE-DOC-01–05 — the retired class-first vision

Persona → cohort → class plan → dish pool. Superseded 2026-07-13.
1. Household → one of 41 FIXED personas RETIRED▸
A household was mapped onto one of 41 hand-authored personas (RE-DOC-02). A persona was a stored label, looked up once — not re-derived per request.
↓
2. Persona → Cohort (RE-DOC-03) RETIRED▸
Each persona carried a cohort assignment feeding CohortPrior in the FinalScore formula: w_cohort·CohortPrior + w_content·ContentMatch + w_history·PersonalHistory + w_context·ContextFit + w_explore·ExplorationBonus − PenaltyTerms.
↓
3. Cohort → Class Plan (26-class taxonomy) RETIRED▸
7 breakfast + 6 lunch + 8 dinner + 5 add-on classes. The cohort determined a class plan — which classes of meal this household should be shown at all. This was the candidate-GENERATION step, not a ranking nudge: dishes outside the plan's classes were never considered.
↓
4. Class Plan → Dish Pool → Hard Constraints (SQL P0 gates) RETIRED▸
Only then were dishes within the planned classes filtered by diet/allergen/ religious/slot/never-list constraints, each requiring a named SQL query returning 0 rows pre-deploy.
↓
5. Weight-ladder interpolation (5 interaction tiers) RETIRED▸
As a household interacted more, FinalScore's weights smoothly shifted from cohort/content-heavy toward personal-history-heavy across 5 named tiers.
↓
6. Cold-start ladder + MMR variety + Never/Not-Today decay RETIRED▸
Day-0→60+ confidence ladder; λ·Relevance − (1−λ)·maxSimilarity variety formula; permanent "Never" suppression vs. exponentially-decaying "Not Today" (P0·e^(−λt)).
↓
7. 4-state DAU evolution (Research → Learning → Cluster → Full-Intelligence) RETIRED▸
The whole engine graduated through 4 modes keyed to daily-active-user volume, eventually reaching cross-user clustering and two-tower/CF ML.

Live today — ghar_re_core + WP-15

Filter → BASE → GAIN → cohort nudge → pairing → Assemble-7. No candidate-generation gate.
1. Household → θ (Derived Household Profile), every request LIVE▸
derivation.derive_theta() computes D1–D7 fields live — income proxy, origin/local blend, adventurousness, household constraints, community prior — with per-field (value, confidence, source) metadata. No stored persona ID; θ is recomputed every call.
↓
2. Hard filters A1–A6 (diet, Jain, allergen, weaning, fasting, calorie) LIVE▸
scoring.eligible() — the ONLY gate that removes dishes from consideration entirely. Unlike the retired class-plan step, nothing about meal "class" ever gates candidates here.
↓
3. BASE score — 8 rule modules (B1–B8), additive LIVE▸
m_palette, m_slot, m_season, sig, m_age, m_household, m_weather, prior_boost — each a plain function summed in scoring.base(). Weather resolves to the household's OWN regional comfort hero (KB §R3), never a generic pakora.
↓
3A. NEW — S_cohort: class-fit nudge from θ-matched cohort NEW · WP-15▸
knowledge.dish_to_class_code() looks up this dish's curated meal-class (131-class taxonomy, Class_Dish_Options_v3, 129/810 real dishes matched — an honest ~16%, never fuzzy-guessed). knowledge.cohort_class_mix() live-matches this household (home_state + household_type + D2 time_route) into Cohort_Matrix_v3's 2952 cohorts and reads that cohort's actual class plan for this slot/day-type. If the dish's class is in that plan, scoring.s_cohort() returns 1.0, else 0.0 — never a filter, never a candidate gate, only a soft additive term.
↓
4. Q15 GAIN — objective-based multiplier LIVE▸
GAIN = 1 + κ·Σ γ[obj]·gs(x). κ pinned 1.0 in v1 (the weight-ladder's successor mechanism — designed, not yet activated; needs real behaviour data).
↓
4A. NEW — score = BASE×GAIN + w_cohort·S_cohort NEW · WP-15▸
Fills the Core Spine master formula's w_cohort·S_cohort term — present in the frozen formula since Spine v1.0, unimplemented until WP-15. w_cohort = 0.15 (modest, given ~16% coverage — see cohort_weights.yaml). w_pref·S_pref remains 0 (v1, no feedback data — same constraint WP-14 already identified).
↓
5. Pairing guardrails + plate_score LIVE▸
pairing.compat() — no two rich gravies, no two same-base, no two dry heroes, region coherence, richness balance. plate_score = scored dry+liquid − λ_pair·compat_penalty.
↓
6. Assemble-7 — greedy select, no-duplicate guard only LIVE▸
7 ranked plates. Variety is currently ONLY a no-duplicate guard — the retired vision's full MMR/decay machinery (left, step 6) is deferred to v2/v3 pending real user history (Final_RE_...md RES-F14), not reinstated by WP-15.
↓
7. RE-DOC-10 phased roadmap (A–G), not a 4-state DAU model LIVE▸
The evolution path today is RE-DOC-10's phase table + WP-14's sequenced plan (module registry → feedback capture → learned module), not the retired 4-state DAU model.
