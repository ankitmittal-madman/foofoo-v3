# Phase 3 — Meal Genome Audit

Evidence-based comparison of RE-DOC-02's 20-dimension "Meal Genome" against (a) the golden-sample
RE fixtures (`ghar_re_core/fixtures.py`), (b) the real production `public.dishes` schema, (c)
`data/source/*` seed CSVs/YAML, and (d) the FROZEN Core Spine (`docs/architecture/ghar-re/
ghar_re_v1_0_core_spine_FROZEN.md`, read in full — 730 lines).

## Headline finding

RE-DOC-02's 20-dim genome and the actually-built engine are **different attribute models that
overlap on content but not on structure**. The Core Spine (frozen 2026, post-dates RE-DOC-02)
reorganizes dish attributes into **five semantic groups (Sensory/Preparation/Nutrition/Structure/
Identity) + one ingredient block (ING)**, ~89 tag dimensions plus scalars — not the 20 named
dimensions of RE-DOC-02. Several RE-DOC-02 dimensions (allergen bitfield, dietary bitfield,
combo pairing array) exist in production but under different mechanisms (trigger-derived bitmask,
separate `dish_combos`/`dish_combo_items` tables) rather than as genome columns; others (festival
relevance, religious compatibility beyond Jain, seasonal affinity as its own field) do not exist
anywhere as real columns.

## Cosine similarity / embeddings check (Phase 3 item 3)

`grep -rn "cosine|embedding|word2vec|vector" ghar_re_core database supabase/functions` returned:
- **Design-only cosine similarity**: the Core Spine specifies `delta_ING = 1 - cosine(v(a),v(b))` (IDF-weighted ingredient overlap, §1.3.3) and `same_base` pairing gate uses `cosine(base-ingredient vectors)` (§4.2). These are **math specifications in the frozen doc, not found instantiated** anywhere in `ghar_re_core/*.py` — `pairing.py:39` explicitly says `"Proxy for the §1 ING base-cosine gate, using MAIN ingredients"`, i.e. the real cosine computation is **not implemented**, only a simplified proxy.
- **"vector" hits** are all either (a) `DictVectorizer`/ML training vectorization in `ghar_re_core/training/train_pref_model.py` (scikit-learn feature vectorization for a *preference* classifier, not a meal-genome embedding), or (b) the production **`genome_vector real[]`** column, which is populated by `fn_update_dish_genome_vector()` (migration 010) as a **plain confidence-ordered array of matched tag positions** (`array_agg(t.confidence ORDER BY tg.vector_position)`), i.e. a **sparse tag-presence vector**, not a learned embedding, and it is never compared via cosine anywhere in the grepped code.
- **Conclusion: no cosine-similarity or embedding-based cross-cuisine discovery is implemented.** It exists only as a frozen-spec formula (§1.3.3/§4.2) and as an inert-schema name (`genome_vector`); the Spine's own Appendix (B, "Learned ingredient embeddings replacing IDF overlap") tags this `[v2]`/OPEN (register ID SP-F6).

## Summary coverage count (20 dimensions)

- **(a) Implemented in the LIVE golden-sample RE** (i.e., present as a populated field the scoring code in `ghar_re_core` actually reads): dims 1,2,3(diff scale),4,5,6,7,8,9(proxy only, real macro exists but only for golden sample),10,11,15,17(Jain only),19 → **~14/20**, several partial/proxy.
- **(b) Present as schema in real production catalogue** (`public.dishes` + `ghar_re.dishes`/related tables): dims 1,2,3(as tag not column),4(tag),5(tag),6(tag),7,8,9(schema exists, not populated for 810),10,11,12(derived enum),13(bitfield),17(Jain),19,20(tables) → **~15/20** have *some* schema home, but several only as tag rows rather than genome columns.
- **(c) Actually seeded with real (non-golden-sample, non-"ai_generated") data**: confidently confirmed populated for the 802/810-dish real catalogue: dims 1,2,7,8,10,19(tier) — **6/20** dimensions have direct evidence of real bulk population in `106_seed_dishes.sql`. Dims 3/4/5/6/13/14/15/17 depend on `dish_tags`/`dish_ingredients` seeding (107/108) which this audit did not row-count in full — flagged as **unverified, not fabricated as populated**.
- **(d) Unused/orphaned** relative to RE-DOC-02's literal spec: dims 12 (bitfield concept replaced by derived enum), 14 (fused into weather_affinity), 16 (festival — no field, only a boost-table tag), 18 (comfort score — decomposed, no stored score), 20 (array replaced by relational tables) → **5/20 dimensions do not exist in the form RE-DOC-02 describes**, though 3 of those 5 have functional equivalents elsewhere.

**Net: of RE-DOC-02's 20 genome dimensions, none is implemented as a literal 1:1 match (same field, same encoding). ~11 have a direct functional analogue that is schema-present and evidenced as populated for at least the golden sample; ~4 more have schema but unverified/partial population; ~5 have no real equivalent and were restructured or dropped in the actually-built (Core Spine) design.**
